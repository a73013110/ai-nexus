# 平台管理與模型政策

管理工作台在 `/admin`，僅有效權限包含 `admin` 的使用者可使用；一般登入不會取得管理權。API 每次查詢與異動皆重新驗證，所有寫入另要求 CSRF。

## 設定第一位管理員

在本機一般設定 `.local/config/appsettings.Local.json` 或正式主機設定中加入：

```json
{
  "Administration": {
    "BootstrapAdministrators": ["it.admin"]
  }
}
```

填 AD 的短帳號，不填密碼、DN 或網域前綴，重啟後端。該帳號下次已驗證的 AD 請求會取得 `administrator` 角色，並在 `access.AdministratorBootstraps` 留下唯一標記與稽核。移除角色後不會因再次登入而自動補回；正式上線後可清空 bootstrap 清單，改由管理後台授權。

## 工作流程

1. 使用者首次 AD 登入建立平台身分與 `member` 角色。
2. 「功能群組與模型」新增群組，勾選功能，視需要限制模型和配額。
3. 「角色」建立工作角色並加入群組。
4. 「使用者」搜尋 AD 帳號，勾選角色；儲存前預覽可用功能，儲存後下一次 API 操作生效。
5. 「異動稽核」檢視操作者、時間、項目與授權識別碼。平台用量顯示最近 30 天的生成與模型實際 token 回報。

主檔使用穩定 ID，名稱可修改。角色與群組可新增、編輯或停用，避免刪除關聯造成不可追蹤的授權歷史；功能由程式與 migration 註冊，管理員調整名稱、順序和啟用狀態。修改功能名稱不會產生新 API。

異動在同一個 serializable transaction 保存授權與稽核。會撤銷操作者自身管理權的變更以 409 拒絕並回滾，避免鎖在管理介面之外；此類變更交由另一位管理員執行。異動 JSON 僅包含授權、模型識別碼及限制，不含提示詞、回覆、密碼或 key。

## 使用者 AI 用量與對話

使用者列表直接顯示最近 30 天生成次數、回報 tokens 與所有對話數。點姓名或用量開啟唯讀活動視窗，包含輸入／輸出 tokens、完成／失敗、AI 任務分類及附件空間。各用量來源透過共用 `UsageReports` 統計 `GenerationRuns` 與 `ModelInvocations`，包含對話及 OCR／文字處理／評測等任務；期間為最近 30 個 UTC 日期，每日分組使用 UTC，顯示時間採台北時區。未回報的 token 不估算。

活動視窗可搜尋標題與本文、瀏覽封存及已刪除的對話；預設包含已刪除的 soft-delete 資料。對話每頁 50 段，內容每次 100 則，按時間顯示資料庫仍保存的所有分支版本，後續訊息可繼續載入。附件提供名稱／大小資訊，沒有新增跨使用者下載或修改權限。

這是獨立的管理唯讀 API：`GET /admin/users/{id}/insights`、`GET /admin/users/{id}/conversations`、`GET /admin/conversations/{id}`（皆帶 `/api/v1` 前綴）。每次重新檢查 `admin` 功能，回應內容前成功保存 `admin.user_usage_read`、`admin.conversations_list` 或 `admin.conversation_read` 稽核。一般 conversations 的 owner 檢查保持有效；管理員不能透過一般 API 修改其他使用者的對話。登入頁會說明管理員授權檢視及稽核。

## 區間費用與價格管理

「AI 費用」進入總覽的平台範圍，可選擇起訖日期、使用者及幣別／費用類型。統計包括聊天、OCR、評測、文字工具、embedding 與連網搜尋；跨模型保留個別價格快照，CSV 匯出整個選定區間，不限畫面已載入的筆數。平台讀取及 CSV 匯出追加稽核。API 費用、內部成本與不同幣別不相加；未定價／缺失 usage 顯示待確認數量。

管理員在總覽「模型價格」新增版本，填供應商、模型 ID、幣別、計費種類、生效 UTC 時間、每百萬 token 與每次呼叫價格。既有版本不可修改，修正需新增版本；舊呼叫不重算。若本地 Ollama 只追蹤資源使用，可明確設為免費；需要分攤設備／電費時設為內部成本並自行維護價格。詳細公式與邊界見 [費用文件](BILLING.md)。

## 異動稽核

角色分派、角色、群組／模型政策、功能異動保存 `resourceKey`、完整 `before`／`after` 快照與結果。驗證失敗／自我鎖定等業務拒絕會回滾，再保存失敗代碼及原值。對話敏感讀取只記錄操作者、資源、分頁與數量，搜尋僅記錄是否套用，不保存搜尋本文、提問或回答。基礎設施無法寫入 SQL 時，既有伺服器錯誤記錄可供排查，不能保證資料庫離線期間仍保存 SQL 稽核。

介面可依帳號／識別碼、動作、結果及台北日期篩選，展開顯示欄位前後差異和原始 metadata。`GET /admin/audit` 支援 `search`、`action`（前綴）、`result`、`from`（含）、`until`（不含）、`before`（ID 游標），每頁最多 100 筆；穩定 ID 游標避免新事件造成重複。時間與 action/resource 游標索引由 `AdministrativeInspectionAudit` migration 維護。

「匯出已載入 N 筆」只匯出目前已載入的篩選結果，檔名明確標示筆數；更多紀錄需先載入。CSV 使用 UTF-8 BOM、正確引號及公式前綴防護。稽核沒有更新／刪除 API；資料庫管理帳號仍應依公司政策限制直接修改資料表的權限。

## 群組模型限制與配額

- 功能授權取有效群組的聯集；模型限制是額外的邊界，取各有效群組限制的交集。
- 不設定模型清單表示不增加限制；空清單表示沒有可用模型。全域 `Inference` 的核准清單、鎖定與隱藏名稱政策仍適用。
- 多個群組的每日次數、附件空間取最低非空設定。無設定時沿用全域上限。
- 每日次數以每位使用者的已建立生成請求計數，UTC 午夜重設；失敗、取消仍計次。相同 idempotency key 的重送不計為新請求，配額耗盡也可取回原結果。
- 附件空間包含原始 SQL binary，限制只阻止新增上傳，不刪除既有資料。

個人設定「使用狀況」顯示當日配額與重設時間。token 統計只合計模型有回報的數量，未提供 usage 的請求明確排除，不把 Context 預估當成實際用量。

目前每個 IIS app 使用一個 worker。使用者日配額已用 SQL row lock 預約，生成也有 executor 租約；全域 GPU 容量與持久聊天排程仍需分散式協調。新的模組應使用同一個模型政策服務並留下用量紀錄。
