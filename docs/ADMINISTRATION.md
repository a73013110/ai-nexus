# 平台管理與模型政策

管理工作區在 `/admin`，僅有效權限包含 `admin` 的使用者可使用；一般登入不會取得管理權。API 每次查詢與異動皆重新驗證，所有寫入另要求 CSRF。

## 設定第一位管理員

在本機一般設定 `.local/config/appsettings.Local.json` 或正式主機設定中加入：

```json
{
  "Administration": {
    "BootstrapAdministrators": ["it.admin"]
  }
}
```

填 AD 的短帳號，不填密碼、DN 或網域前綴，重啟後端。該帳號下次已驗證的 AD 請求會取得 `administrator` 角色，並在 `access.AdministratorBootstraps` 留下唯一標記與稽核。移除角色後不會因再次登入而自動補回；正式上線後可清空 bootstrap 清單，改由管理後台授權。

使用者清單支援新增、編輯、停用及移除。每位使用者可啟用 AD、本地密碼或兩者，兩種登入皆對應同一個 UserId、角色與私人資料。手動預建 AD 帳號填目錄短帳號，首次成功的目錄驗證才綁定 SID；已綁定的 AD 使用者不能換綁他人的帳號。手動姓名不會被後續目錄登入覆蓋。移除為邏輯刪除，保留歷史對話、稽核與登入名稱，防止重建同名帳號接管資料。

本地密碼採 Argon2id PHC 格式（64 MiB、3 iterations、parallelism 1、128-bit 隨機 salt），不保存可還原的密碼；API、前端及稽核只顯示是否已設定。密碼需 12–128 字元，支援密碼管理器。登入有 IP 限流；連續 5 次失敗暫鎖 15 分鐘，管理員重設密碼可解除。本地姓名與 bootstrap AD 帳號相同也不會取得管理權。停用、改登入政策或重設密碼會撤銷舊 cookie。管理者不能移除自己、停用自己目前的登入方式或撤銷自己的管理權。

功能清單、群組的功能選取及授權預覽與側欄共用 `core/feature-groups.ts` 的分類，依「工作」「協作與品質」「系統」呈現；新功能未分類時進入「更多工具」，不會消失。名稱、排序、啟用狀態皆取自同一份資料庫功能目錄；側欄不再另設簡稱。「檔案庫」為正式功能，可於群組授權或停用，其 API 也檢查 files 權限。升級時為既有 chat／knowledge／projects 群組補上檔案庫授權，保留原有存取範圍。

## 管理者測試身分

已登入的使用者可由帳號選單「切換登入方式」重新選擇 AD／Windows 或本地密碼；從本地切回 Windows 時先以受 CSRF 保護的登出清除 cookie，再驗證 Windows 身分。測試期間登出或成功重新登入也會結束測試、保存稽核並撤銷該次測試 cookie。

使用者操作選單的「測試此身分」需填寫目的，無須知道目標密碼。伺服器重新驗證管理權後簽發限時 15 分鐘的測試 cookie，保存來源管理者 ID／登入版本與目標 ID／登入版本。畫面持續顯示測試身分、來源與返回按鈕；切換時完整載入工作區，取消既有串流並清除記憶體資料及草稿狀態，其他分頁收到通知後重新載入。

測試時目標的功能權限、資料 owner、配額與模型政策皆生效，新增或修改業務資料會實際保存。管理 API 在測試身分下僅允許讀取，禁止管理設定寫入與巢狀切換。開始、返回及自動到期記錄稽核；測試期間的請求稽核同時記錄實際操作者 ActorId 與目標 OwnerId，管理清單及 CSV 顯示兩者。每次測試有獨立識別碼，返回後舊測試 cookie 即不可重播；使用既有稽核 ResourceId 索引檢查，無須掃描 JSON 或另建重複資料表。

返回不要求目標具有管理權。每次 cookie 請求重新檢查來源登入與管理權；來源被撤銷時登出，目標被停用／改登入或到期時只返回仍有效的來源管理者。到期瞬間跨越身分的業務請求會先以 409 阻擋，不會改用原管理者執行；回應附身分識別，前端重新載入，避免舊畫面接收另一身分的資料。已建立的背景工作及已開啟 SSE 依原生命週期完成，不會因切換移轉 owner。相同瀏覽器分頁共用登入，若要同時測試獨立登入請用不同瀏覽器 profile。

## 工作流程

1. 使用者首次 AD 登入建立平台身分與 `member` 角色。
2. 「功能群組與模型」新增群組，勾選功能，視需要限制模型和配額。
3. 「角色」建立工作角色並加入群組。
4. 「使用者」搜尋 AD 帳號，勾選角色；儲存前預覽可用功能，儲存後下一次 API 操作生效。
5. 「異動稽核」檢視操作者、時間、項目與授權識別碼。平台用量檢查最近 30 天的活躍使用者、完成／失敗／取消、各模型輸入／輸出、缺失用量、使用來源，以及所有期間的原檔容量。另顯示模型供應商連線與搜尋設定；區間費用、價格與 CSV 仍由「用量與費用總覽」處理。

主檔使用穩定 ID，名稱可修改。角色與群組可新增、編輯或停用，避免刪除關聯造成不可追蹤的授權歷史；功能由程式與 migration 註冊，管理員調整名稱、順序和啟用狀態。修改功能名稱不會產生新 API。

異動在同一個 serializable transaction 保存授權與稽核。會撤銷操作者自身管理權的變更以 409 拒絕並回滾，避免鎖在管理介面之外；此類變更交由另一位管理員執行。異動 JSON 僅包含授權、模型識別碼及限制，不含提示詞、回覆、密碼或 key。

## 使用者 AI 用量與對話

使用者列表直接顯示最近 30 天生成次數、回報 tokens、所有對話數及原檔容量。點姓名或用量開啟活動與政策視窗，分為「對話」「AI 模型」「附件容量」。對話頁保留完整閱讀高度；個人政策與容量在各自分頁調整。用量透過共用 UsageReports 統計 GenerationRuns 與 ModelInvocations，包含聊天、OCR／文字工具／評測、累計耗時及有耗時紀錄的請求數。期間為最近 30 個 UTC 日期，顯示時間採台北時區；未回報的 token 不估算。

對話與管理內容可展開每次回答的總耗時、排隊、執行及輸入／輸出 tokens；完成、取消、失敗及租約回復均保存時間。執行時間包含 Context 準備及等待 provider 容量，不是供應商純運算時間。SQL 同列保存 provider／原生模型、時間及 tokens，供後續管理分析。

容量顯示已用／上限／剩餘，管理者輸入十進位 GB，可精確到一個 byte。`PUT /api/v1/admin/users/{id}/storage` 接收整數 limitBytes（0–1,000,000,000,000,000），0 禁止新增上傳，null 恢復繼承。個人 override 優先於群組與預設 5 GB，因此調高能正確生效；降低不刪既有檔案。變更保存 admin.user_storage 前後快照，測試身分禁止管理寫入。

活動視窗可搜尋標題與本文、瀏覽封存及已刪除的對話；預設包含已刪除的 soft-delete 資料。對話每頁 50 段，內容每次 100 則，按時間顯示資料庫仍保存的所有分支版本，後續訊息可繼續載入。附件提供名稱／大小資訊，沒有新增跨使用者下載或修改權限。

這是獨立的管理唯讀 API：`GET /admin/users/{id}/insights`、`GET /admin/users/{id}/conversations`、`GET /admin/conversations/{id}`（皆帶 `/api/v1` 前綴）。每次重新檢查 `admin` 功能，回應內容前成功保存 `admin.user_usage_read`、`admin.conversations_list` 或 `admin.conversation_read` 稽核。一般 conversations 的 owner 檢查保持有效；管理員不能透過一般 API 修改其他使用者的對話。登入頁會說明管理員授權檢視及稽核。

## 區間費用與價格管理

「用量與費用總覽」進入總覽的平台範圍，可選擇起訖日期、使用者及幣別／費用類型。統計包括聊天、OCR、評測、文字工具、embedding 與連網搜尋；跨模型保留個別價格快照，CSV 匯出整個選定區間，不限畫面已載入的筆數。平台讀取及 CSV 匯出追加稽核。API 費用、內部成本與不同幣別不相加；未定價／缺失 usage 顯示待確認數量。

管理員在總覽「模型價格」新增版本，填供應商、模型 ID、幣別、計費種類、生效 UTC 時間、每百萬 token 與每次呼叫價格。既有版本不可修改，修正需新增版本；舊呼叫不重算。若本地 Ollama 只追蹤資源使用，可明確設為免費；需要分攤設備／電費時設為內部成本並自行維護價格。詳細公式與邊界見 [費用文件](BILLING.md)。

## 異動稽核

角色分派、角色、群組／模型政策、功能異動保存 `resourceKey`、完整 `before`／`after` 快照與結果。驗證失敗／自我鎖定等業務拒絕會回滾，再保存失敗代碼及原值。對話敏感讀取只記錄操作者、資源、分頁與數量，搜尋僅記錄是否套用，不保存搜尋本文、提問或回答。基礎設施無法寫入 SQL 時，既有伺服器錯誤記錄可供排查，不能保證資料庫離線期間仍保存 SQL 稽核。

介面可依帳號／識別碼、動作、結果及台北日期篩選，展開顯示欄位前後差異和原始 metadata。`GET /admin/audit` 支援 `search`、`action`（前綴）、`result`、`from`（含）、`until`（不含）、`before`（ID 游標），每頁最多 100 筆；穩定 ID 游標避免新事件造成重複。時間與 action/resource 索引包含於 InitialCreate。

「匯出已載入 N 筆」只匯出目前已載入的篩選結果，檔名明確標示筆數；更多紀錄需先載入。CSV 使用 UTF-8 BOM、正確引號及公式前綴防護。稽核沒有更新／刪除 API；資料庫管理帳號仍應依公司政策限制直接修改資料表的權限。

## 個人與群組模型政策

群組編輯分為基本資料、功能授權、AI 模型與附件容量，使用較寬視窗與固定儲存區。個人與群組共用同一個模型政策元件，按模型設定每日 token 上限，已移除每日生成次數限制。

- 功能授權取有效群組聯集；模型白名單取各有效群組及個人限制的交集，全域核准／鎖定／隱藏政策仍適用。
- 模型清單 null 表示不增加限制，空陣列禁止所有模型。各模型的每日上限合計輸入與輸出，0 禁止該模型生成；留空繼承。群組上限按每位使用者計算，多個有效群組取最低值；個人逐模型覆寫優先，可提高或降低，未覆寫的模型仍繼承群組。
- `/api/v1/admin/users/{id}/model-policy` 的 GET 回傳個人與有效政策，PUT 接收 `allowedModelIds`、`dailyTokenLimits`（模型路由 → 整數 tokens），保存 `admin.user_model_policy` 前後快照；管理寫入需管理權與 CSRF，測試身分不可寫入。
- `/api/v1/settings/model-policy` 回傳各模型實際回報、預留、剩餘與來源；隱藏模型政策使用公開別名，不揭露原生模型名稱。
- 配額依請求建立時的 UTC 日期計算，台北每日 08:00 重設，與伺服器本地時區無關；跨午夜準備的請求仍使用同一個日期結算。聊天、OCR、文字工具、評測共用政策；embedding 與搜尋有自己的服務配額，不占聊天模型預算。
- 建立請求時以 SQL 使用者 row lock 串行預約，以保守 UTF-8／圖片估計預留輸入與最大輸出；剩餘預算較少時降低本次輸出上限，並保留原先的歷史裁切預算，避免同時請求超額。
- 完成後以完整回報的輸入＋輸出結算。執行中或缺少完整 usage 的失敗／取消仍保留預留額度至該 UTC 日期結束；尚未執行的排隊取消／租約回復則釋放。預留是配額保護值，與實際用量分開顯示，不把估計當成實際 token。
- 相同 idempotency key 重送可取得原結果，即使目前配額耗盡仍可讀取。供應商回報若超過保守估計，實際用量仍完整保存並阻擋後續請求；上限依供應商是否遵守輸出限制及圖片估計精度。
- 附件容量依個人覆寫、有效群組最低值、網站預設 5 GB 決定。原檔包含草稿、pending 預約與 deleting 重試，多處引用只計一次，實體刪檔成功才釋放容量。

升級前停止舊 host，再套用 `PerModelTokenBudgets` migration（或 DBA 審閱 `db/migrations.sql`）。既有每日請求次數不能換算成 token，升級後需按模型設定 token 預算；既有模型白名單、容量與使用紀錄保留。migration 只更新原始預設功能名稱，管理者自訂名稱保留。

每個 IIS app 使用一個 worker；使用者預算採 SQL row lock，聊天有 executor 租約，全域 GPU 容量與排程仍在程序內協調。新模組應使用同一個模型政策服務並保存用量與預留，不自行重複計算。
