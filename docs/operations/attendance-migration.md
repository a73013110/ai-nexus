# 出勤舊資料轉移

結論：以 [`deploy/sql/attendance-legacy-migration.sql`](../../deploy/sql/attendance-legacy-migration.sql) 把舊系統 ADAuthentication 的卡號對應與刷卡轉進 `attendance`。先預覽、處理清單，舊系統停止匯入後才寫入；可重跑，已存在的不重複寫、不覆寫。為什麼這樣轉見 [ADR 0018](../decisions/0018-attendance-cards-and-punches.md#舊資料轉移)。

## 前置條件

- 在舊庫所在主機（ADAuthentication 與 GD 同機）以 SSMS 的 SQLCMD 模式執行；用 `sqlcmd` 時加 `-I -f 65001`（腳本是 UTF-8）。
- 該主機有指向本系統資料庫主機的 linked server，登入身分可讀 `identity.Users`、讀寫 `attendance`。不開跨伺服器交易，不需要 MSDTC。
- 來源庫的 `dbo.syn_eDoc_Sys_User` 指向 GD 的 `Sys_User`（舊系統原本就用它換帳號）。
- 本系統已部署出勤資料表；要對到人的同仁在 `identity.Users` 已有 `AdAccount`（登入過或管理者預先建立）。
- tempdb 要容得下整份 `EmpClock`（暫存表）。

## 變數

腳本開頭的 `:setvar`，說明寫在腳本裡。常改的是 `Apply`（0 預覽、1 寫入）、`TargetServer`（linked server 名稱）、`TargetDatabase`、`SourceDatabase`、`BatchSize`（每批刷卡筆數，預設 50000）。

- `LegacyMachineCode`、`LegacyEventCode`：舊表沒存打卡檔的第一欄與最後一欄，預設 `001`、`11`。**機器代號是刷卡去重鍵的一部分**，必須與打卡檔相同，日後匯入同一天的檔才會認成同一筆；現有打卡機是 `001`（2026-10-22 確認），換機或多台時再改。
- `UnmatchedAsHolderName`：預設 0，對不上使用者的期間不寫。設 1 改以舊系統姓名寫入（`UserId` 為空），HR 之後在卡號對應頁綁人；代價是這些卡不會出現在未歸戶清單。

## 步驟

1. **預覽**：`Apply 0` 執行，看結果集：摘要（各表將新增筆數、批次數）、對不上的人、無法寫入的持有期間、無法轉入的刷卡、注意、將新增的持有期間。
2. **處理清單**（依「原因」）：
   - `Users 沒有此 AD 帳號`：在使用者管理預先建立該帳號，或請本人登入一次。
   - `Sys_User 沒有此公文帳號`、`ACCOUNT 空白`、`同一 ID 有多個 ACCOUNT`：在 GD 或舊庫 `EmpCard.Account` 修正。
   - `公文帳號（Account）空白`、`都沒有此職號`：在舊庫補 `EmpCard`；不處理也可以，這些刷卡照轉，轉入後在未歸戶卡號指派。
   - 與目標既有期間重疊、訪客卡：轉入後由 HR 在卡號對應頁人工建立。
3. **寫入**：停用新系統的排程匯入（`Attendance:Import:Enabled` 設 `false`）、確認舊系統已停止匯入，`Apply 1` 執行。訊息會印出每批進度與預估剩餘時間。
4. **重跑**：中斷或失敗直接再跑 `Apply 1`。最後跑一次 `Apply 0`，摘要的「將新增」都應為 0。再恢復排程匯入。

## 對應規則與邊界

- **卡號**：去掉前後空白，1～32 字、不含控制字元，比對不分大小寫（同匯入程式）；刷卡日期限 2000～2099 年。不符的刷卡不轉，列在「無法轉入的刷卡」。
- **時間**：舊表是台灣時間，存成 `+08:00`；出勤日取刷卡時間的日期。`CreatedAt` 與匯入紀錄用 UTC。
- **刷卡**：全部轉入（含 `UNKNOWN_`），掛在檔名 `legacy-adauthentication` 的 `PunchFiles` 列下，並寫一筆 `manual`、沒有操作者的匯入紀錄（匯入紀錄頁看得到）。這個檔名不是 `yyyyMMdd.txt`，排程與手動重匯都不會碰它；日後匯入的每日檔遇到同一筆刷卡會視為已存在而略過。
- **卡片**：舊系統認得持有人的卡（有非 `UNKNOWN_` 刷卡或現行 `EmpCard` 對應）登錄為員工卡；只出現在 `UNKNOWN_` 的卡不登錄，以未登錄卡號出現在未歸戶清單，由 HR 決定是員工卡或訪客卡。
- **持有期間**：同一卡號依時間排序，職號連續相同的一段刷卡＝一段期間，`UNKNOWN_` 段只用來分隔、不轉。
  - 開始＝該段第一筆刷卡；結束＝該段最後一筆刷卡＋1 秒（不含），不接到下一人的開始，兩人之間的 `UNKNOWN_` 刷卡才不會歸給前一人。
  - 卡上最後一段且就是現行 `EmpCard` 對應的人：結束為空（持有中）。
  - 現行對應的人在這張卡上沒有刷卡（新發卡、或接手後還沒刷）：從 `EmpCard.UpdateDTTM` 起持有中，不早於前一段的結束。
  - A→B→A 輪回切成三段，列在「注意」。舊系統兩人以上掛同一卡號時，不建持有中的期間，列在「無法寫入」。
- **職號 → 使用者**：`EmpCard.Account`（找不到職號時用 `EmpCardLog` 最近一筆有帳號的列，即已刪除的對應）→ `Sys_User.ID` → `ACCOUNT` → `Users.AdAccount`，去空白、不分大小寫。已刪除的使用者照樣對上（列在「注意」），歷史刷卡仍屬於他。
- **冪等**：卡號已登錄就不新增；同一張卡、同一開始時間的期間視為已轉過，不比對持有人與結束時間，也不覆寫 HR 之後的修改；與目標既有期間重疊的不寫。刷卡以（卡號、時間、機器代號）去重。

## 事後檢查

- 卡號對應頁的未歸戶卡號：應只剩 `UNKNOWN_` 卡、對不上的人與清單中無法寫入的卡。
- 匯入紀錄頁有 `legacy-adauthentication` 的紀錄，筆數是舊系統轉入的刷卡總數。
- 抽幾位同仁看出勤紀錄，與舊系統同期的上下班時間一致。
- 不必刪除舊表；確認無誤後再停用舊系統。
