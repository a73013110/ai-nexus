# 功能使用量

「功能使用量」頁回答兩個問題：哪些功能有人用、用了多少，以及誰用得最多。

- 位置：`/admin/audit/usage`，功能 ID `audit.usage`。
- 授權與資料範圍：與[活動稽核](activity-audit.md)相同的規則，但要另外授予 `audit.usage`。初始給 administrators 群組。

## 怎麼算

- 只從稽核紀錄的 `FeatureId`（通過授權的功能）統計，不另建使用量表，也不在前端埋點。規則見 [ADR 0023](../decisions/0023-audit-standard.md)。
- **只算宣告稽核的端點**：輪詢、選單這類不稽核的呼叫不計入。如果某個頁面的端點全都不稽核，這個頁面不會出現在報表裡。
- **動作功能併入所屬頁面**：例如 `attendance.cards.maintain` 算在 `attendance.cards`。同一個人用了頁面也用了它的動作，只算一人。
- **人數與次數只算成功的操作**：失敗與授權拒絕另外計成「失敗或拒絕」。
- **使用者指實際操作者**：用測試身分操作時，算在管理者本人身上。
- **重複查詢已在寫入時合併**（10 分鐘內同條件只記一次），所以次數比較接近「操作次數」，而不是「請求數」。

## 畫面與 API

- 期間：7、30、90 天，終點都是今天。API 可以指定任意期間，最長 366 天。
- 摘要：有人使用的功能數、操作次數、失敗或拒絕次數。
- 列表：每個功能的使用人數（長條）、操作次數、失敗率與最後使用時間，依使用人數排序。
- 點一列會開啟詳情，內容是每日使用人數的趨勢，以及使用最多的 20 人。「查看這段期間的稽核紀錄」會帶著功能與期間開啟活動稽核頁。
- API：
  - `GET /api/v1/admin/audit/usage`：列表。
  - `GET /api/v1/admin/audit/usage/{featureId}?offsetMinutes=`：單一頁面的詳情。依 `offsetMinutes` 指定的時區分日；動作功能的 ID 回 404。
  - 兩支 API 本身都會記為 `audit.usage.read`。

## 驗證

- `FeatureUsageTests`：併入頁面、期間、時區分日、測試身分歸屬與權限。
