# 帳號安全：通知信箱與登入方式

## 帳號與通知信箱

- 帳號只有兩個欄位：`AdAccount`（AD 短帳號 `sAMAccountName`，不含網域）與 `LocalAccount`（本地登入帳號），至少一個（`ck_Users_LoginName`）。畫面、搜尋、排序與稽核顯示的帳號是 AD 帳號，沒有才用本地帳號。
- 帳號保留目錄或使用者輸入的大小寫，比對一律不分大小寫（資料庫定序 CI 與唯一索引）；只改大小寫不算改名。
- AD 表單登入只用帳號名（`sAMAccountName`）。輸入 `DOMAIN\chen`、`chen@<AD 網域>` 或 `Identity:ActiveDirectory:AccountSuffixes` 列出的後綴時會自動去掉；其他 `@` 輸入與帳密錯誤同一回應。
- 通知信箱 `Users.Email` 只用來寄驗證碼與帳號安全通知，不是登入識別、不唯一（共用信箱、別名）。來源 `EmailSource`：

| 來源 | 寫入時機 | 本人可改 |
| --- | --- | --- |
| `directory` | AD／Windows 登入或管理員[從 AD 匯入、更新](directory-import.md)時讀目錄 `mail`，寫入即視為已驗證；目錄移除 `mail` 時一併清空 | 否 |
| `user` | 本人以驗證碼驗證新地址 | 是 |
| `admin` | 管理員在使用者詳情設定（[管理員設定信箱](#管理員設定信箱)）；本人驗證前視為未驗證 | 是 |

- 目錄只覆寫「沒有信箱」或「來源是 `directory`」的值；`ProfileManaged=1`（管理員維護個人資料）的使用者姓名與信箱都不被目錄覆寫。
- 每次 AD 驗證成功（LDAP 登入、Windows 驗證的請求，至多每 5 分鐘寫一次）更新 `DirectoryVerifiedAt`，供本地密碼新鮮度規則使用；管理員匯入或從 AD 更新不算驗證，不寫入。

## 管理員設定信箱

使用者詳情的「通知信箱」頁籤（`identity.users` 授權，`PUT /api/v1/admin/users/{id}/email`，空值清除）：

- **AD 提供的信箱不可覆寫或清除**（`email_managed_by_directory`）：下次登入會被目錄同步蓋回，介面唯讀並說明來源。清除後 `EmailSource` 為空，AD 使用者下次登入會再由目錄寫入。
- **設定的地址一律未驗證**（`EmailSource=admin`、`EmailVerifiedAt` 為空）：管理員無法證明使用者持有該信箱，若視為已驗證，管理員帳號被盜時可把步升驗證碼導到攻擊者的信箱。步升驗證碼與安全通知只用已驗證的地址；本人在設定頁以驗證碼確認後才轉為 `user`。
- 與本人設定相同的檢查：格式、他人已驗證的地址不可用（`email_in_use`）；與目前地址相同時不變更，保留既有的驗證。
- **不遞增 `SecurityVersion`**：未驗證的地址不授予任何能力，不必登出使用者。
- 原本有已驗證的信箱時，通知寄到舊信箱（同一範本，註明由管理員執行、只含遮罩後的新地址），與變更同一交易入列。
- 稽核 `admin.user_email`，前後快照只記遮罩後的地址、來源與是否已驗證。

## 自助維護（設定 → 帳號與權限）

| 資料 | 本人可改 |
| --- | --- |
| 姓名、AD 帳號、角色 | 否（姓名出現在稽核與協作，自改等於可冒名） |
| 通知信箱 | 來源不是 `directory` 時可設定或變更，須以寄到新地址的驗證碼確認 |
| 本地登入（帳號名＋密碼） | `Identity:SelfService:LocalLogin=true` 時可啟用、改名、改密碼；AD 使用者可建立本地密碼當備援 |
| 停用本地登入 | 可，但本地是唯一登入方式（管理員關掉 AD 登入）時不可 |

- **步升驗證**：改信箱與本地登入前要在 `ReauthenticationMinutes`（10 分鐘）內重新證明身分：目前登入方式的密碼（本地密碼沿用失敗鎖定；AD 密碼須驗出同一個 SID，需設定服務帳號），或寄到**已驗證**信箱的驗證碼。Windows 整合驗證每個請求都重新驗證，視為已步升。兩種都不可用時請管理員協助。
- **驗證碼**：6 位數、只存 HMAC 雜湊、15 分鐘、錯 5 次作廢、成功一次即失效，同用途只有最新一組有效；每人每小時最多 5 封、同用途 60 秒內不重寄。信件是敏感信（內文加密、寄出後刪除、不可重寄），不含連結；設定頁可看到「寄送中／已寄出／失敗」。
- **變更後**：遞增 `SecurityVersion` 撤銷其他工作階段，重發目前的 cookie 並回傳新的 CSRF token（claims 變了，舊 token 失效）；停用的正是目前的本地登入時直接登出。改信箱時通知舊的已驗證信箱，本地登入變更時通知目前的已驗證信箱。
- **限流**：寄碼、步升、確認信箱每人每分鐘 10 次；本地登入變更每人每分鐘 5 次。測試身分一律唯讀。
- **稽核**：`account.*`（歸在「登入與身分」）記遮罩後的信箱、本地帳號名與步升方式，不含密碼、驗證碼或雜湊。
- 本地密碼除 12–128 字元外，不可包含帳號名、不可是常見密碼（不分大小寫比對約一萬筆 12 字元以上的外洩密碼，清單與授權在 `backend/src/AiNexus.Features/Admin/Identity/SelfService/`）或連續字元（`PasswordPolicy`）；帳號名不可與他人的本地或 AD 帳號相同。

## 本地密碼的 AD 新鮮度

預設關閉（`Identity:SelfService:DirectoryFreshnessDays` 為 0）：AD 使用者可自行建立本地密碼並一直使用。設為 N（1–365）天時，AD 綁定（SID 不是 `managed:`）且仍允許 AD 登入的使用者，最近一次 AD 驗證超過 N 天就不能用本地密碼登入，回 403 `directory_verification_required`，先用 AD 登入一次即恢復。

- 目的：AD 帳號停用（離職）後，使用者自行設定的本地密碼最晚在期限後失效；未開啟時只能靠管理員停用帳號（立即失效）。
- 只在密碼正確後才回這個代碼，密碼錯誤仍是一般的帳密錯誤。
- 管理員關掉 AD 登入的帳號是明確的本地專用帳號，不套用。
