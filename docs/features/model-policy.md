# 模型政策與配額

- 模型授權與每日 token 額度由群組與個人政策合併而成；附件容量另有一套「個人優先」的規則。
- `ModelPolicyResolver` 集中純政策合併，`ModelPolicyService` 結合有效群組、用量與預留。新模組要用同一個服務保存用量與預留，不要自行計算。
- 管理介面：群組編輯分為基本資料、功能授權、AI 模型與附件容量；個人與群組共用同一個模型政策元件。操作入口見 [平台管理](administration.md)。

## 模型授權

- 功能與模型授權取有效群組的**聯集**。群組模型清單為 null（或未保存政策）代表授予全部平台模型；空陣列代表此群組不授予模型，但不影響其他群組。沒有有效群組時不授予模型，管理員也一樣。
- 全域的核准／鎖定／隱藏政策與供應商可用性仍然適用。
- 個人模型清單為 null 時繼承群組結果；有清單時與群組結果取**交集**，只能限縮。個人空陣列禁止此帳號使用所有模型。

## 每日 token 額度

- 每個模型的上限合計輸入與輸出，按使用者計算。只合併**有授權該模型**的群組額度並取最高值，不加總；任一授權群組留空即無上限。群組 0 代表該群組不提供額度。
- 個人逐模型覆寫優先，可提高、降低或以 0 禁止；留空則繼承群組結果。
- 配額以請求建立時的 UTC 日期計算（台北每日 08:00 重設），跨午夜的請求仍用同一日期結算。
- 聊天、OCR、文字工具、評測共用模型政策；embedding 與網路搜尋有各自的服務配額，不占聊天模型預算。

## 預約與結算

- 建立請求時以使用者 SQL row lock 串行預約，用保守的 UTF-8／圖片估計預留輸入與最大輸出；剩餘預算較少時降低本次輸出上限，避免同時請求超額。
- 完成後以回報的輸入＋輸出結算。執行中或缺少完整 usage 的失敗／取消保留預留到該 UTC 日結束；尚未執行的排隊取消與租約回復則釋放。預留是保護值，與實際用量分開顯示。
- 相同 idempotency key 重送取得原結果，即使配額已用完也能讀取。供應商回報超過估計時照實保存並阻擋後續請求。

## API

- `GET`／`PUT /api/v1/admin/users/{id}/model-policy`：個人與有效政策；PUT 接收 `allowedModelIds`、`dailyTokenLimits`（模型路由 → 整數 tokens），保存 `admin.user_model_policy` 前後快照。測試身分不可寫入。
- `GET /api/v1/settings/model-policy`：本人各模型的實際回報、預留、剩餘與來源；隱藏模型使用公開別名，不揭露原生名稱。

## 附件容量

- 有效上限＝個人覆寫 → 有效群組的最低非空上限 → 網站預設 `Attachments.DefaultOwnerLimitBytes`（5 GB）。個人覆寫可以超過群組與預設；0 禁止新上傳，降低上限不刪既有檔案。
- 用量包含草稿、pending 預約與 deleting 重試中的原檔；多處引用只計一次，實體刪檔成功才釋放。
- `PUT /api/v1/admin/users/{id}/storage` 接收整數 `limitBytes`（0–1,000,000,000,000,000），null 恢復繼承；介面輸入十進位 GB。變更保存 `admin.user_storage` 前後快照。細節見 [附件保存](attachment-storage.md)。

## 部署限制

每個 IIS app 一個 worker：使用者預算靠 SQL row lock，聊天有 executor 租約，但全域 GPU 容量與排程仍在程序內協調（見 [ADR 0001](../decisions/0001-single-iis-in-process-locks.md)）。
