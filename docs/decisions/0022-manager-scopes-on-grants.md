# 0022 主管範圍存在每一筆授權上

- **狀態**：採用（2026-10-27），取代 [ADR 0017](0017-organization-units-and-data-scopes.md) 的「主管範圍」一節。
- **實作**：已完成。`accesscontrol.RoleGroupFeatures.ManagerScope`、`FeatureDefinition.ManagerScopes`、`IDataScope`；規則見 [資料範圍](../architecture/data-scopes.md#主管範圍)。
- **決定**：
  - 授權從（群組, 功能, 範圍）變成（群組, 功能, 範圍, 主管範圍）。範圍給群組的所有成員；主管範圍是成員中組織勾選為主管的人另可看的，兩者以 OR 合併。
  - 主管範圍的代碼與成員範圍分開：`managed`（所管單位）、`managed-tree`（所管單位及下層），不沿用 `unit`、`unit-tree`。
  - 功能在頁面目錄以 `ManagerScopes` 宣告可選哪些；沒宣告的功能，授權不能帶主管範圍。管理介面每個功能兩組選擇：「所有成員」與「主管另可看」（可選不另外）。
  - 主管是誰仍只來自組織的主管勾選（`organization.UnitMembers.IsManager`），不建主管群組。

## 為什麼改

- 原本的主管範圍寫死在目錄（出勤紀錄 `unit-tree`），群組上看不到：`workspace` 的出勤紀錄顯示「本人」，主管卻看得到所管單位，管理員會誤會。
- 寫死就無法逐群組關閉：要取消只能改主管勾選（影響所有功能）或改程式。存在授權上，管理員在群組畫面就看得到、改得到，群組停用時也一併失效。
- 「所屬」與「所管」意思不同：主管範圍沿用 `unit-tree`，存取預覽就顯示成「所屬單位及下層」。另立代碼，名稱與計算都不混淆。

## 沒有因此多一份主管資料

- 授權只記「這個群組的主管另可看多少」，不記誰是主管；誰是主管仍由組織勾選決定，調任或卸任只改組織，範圍跟著變。
- 不是主管的人，即使群組給了主管範圍，有效範圍也不含 `managed*`（畫面據此決定版面，不會讓一般人看到選人欄位）。
- 成員範圍已是 `all` 時不另外計算主管範圍。

## 擴充

- 每個範圍在 `DataScopes` 宣告依據哪種單位（所屬、所管）與是否含下層，`IDataScope` 依宣告計算，不分辨範圍來源。新增依單位的範圍只要加宣告。
- 「所管單位」由 Organization 的 `IUnitMembership` 回答。首長單位（[ADR 0024](0024-head-units.md)）就是只改這裡怎麼算所管單位，授權與範圍代碼不變。

## 不採用

- **繼續寫死在目錄、只在畫面提示**：問題不是看不到，而是改不了。
- **主管群組**（把主管加進一個群組授權）：兩份主管資料，調任時只改一邊範圍就錯。
- **主管範圍沿用 `unit`／`unit-tree`、以欄位區分**：代碼相同但意思不同，結果的 `Scopes` 會分不出來源，存取預覽的名稱也會錯。
