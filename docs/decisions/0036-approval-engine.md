# 0036 簽核引擎：線性關卡、審核人規則外掛、指派實體化

- **狀態**：採用（2026-11-13）；第一個使用者是[儲存庫權限](0037-repository-access-per-person.md)。
- **決定**：
  - 模組 `Flow`（Office 區，資料表在 schema `flow`）負責簽核的狀態、指派、提醒、代審與畫面。業務模組只決定「申請什麼」與「結束後做什麼」，不各自寫流程。
  - **流程**是依序進行的關卡，每個**申請種類**（kind）一條，由管理員在「簽核流程」頁設定；要依申請內容走不同的路，用關卡條件，不另建多條流程。每個種類要有種子（`database/App/Seed/flow.sql`），沒有流程時送出失敗。
  - **審核人規則**是外掛：關卡只存規則鍵與 JSON 參數，引擎呼叫對應的 `IApproverRule` 算出候選人。內建三種：
    - `applicant-manager`：申請人的主管，參數是往上幾層（1 到 5）。
    - `users`：指定人員（最多 20 位）。
    - `feature-holders`：持有某功能的人。
    - 業務模組可註冊自己的規則（例如 `repository-stewards`），並限定只給自己的種類使用。
  - **條件**：關卡可設「某事實等於某值才需要」。事實由種類宣告、送出時提供（例如 `permission=write`）；只支援單一等式。
  - **申請種類**實作 `IFlowKind`，以 `AddFlowKind` 註冊並宣告名稱與事實。申請結束時引擎在同一交易呼叫它的 `CompleteAsync`；回傳失敗時整筆決定回滾，決定的人看到原因（例如儲存庫已停止申請）。
  - **送出時快照**：關卡與參數、顯示用的標題與欄位都存進申請。之後改流程不影響進行中的申請，通用畫面也不必認得每種申請。
  - **指派實體化**：關卡啟動時把候選人寫成指派列（申請＋使用者），「待我審核」只是索引查詢。排程 `flow.maintenance`（每 15 分鐘）依目前的組織與授權重算指派、處理逾期；按下決定時再即時重算一次，不在名單內就拒絕。
  - **決定帶關卡序號**：送出的是畫面上看到的那一關；關卡已被別人推進時回 `flow_instance_changed`，不會把下一關一併核掉。
- **引擎統一處理的規則**：
  - 每關任一人核准即通過，任一關退回即結束；申請人在結束前可以撤回，超過 `Flow:ExpireAfterDays` 未完成自動逾期。
  - 申請人不審自己：從候選人排除。
  - 主管鏈跳過沒有主管的單位，往上到頂為止（含[首長單位](0024-head-units.md)）。規則算不出人時交給持有 `flow.approvals.manage` 的人，關卡註記為改由簽核管理員。
  - 候選人中有人已核准本申請前面的關卡：這關自動通過並註記，不讓同一人連按兩次。
  - 條件不成立的關卡記為略過，畫面照樣列出整條流程；沒有任何適用關卡時直接核准。
  - 持有 `flow.approvals.manage` 的人可代審，稽核與畫面都記為代審。
- **原因**：
  - 儲存庫權限只是第一個。「申請 → 主管 → 負責人」這類需求還會出現；狀態、指派、提醒、代審與畫面每次重寫，既重複又容易行為不一致。
  - 線性關卡加單一條件，已涵蓋公司內常見的簽核，管理員也看得懂、設得出來。BPMN 這類通用引擎的設定與除錯成本遠高於需求。
  - 一個種類一條流程：要分流的情況用條件表達，管理員只維護一處；個別業務物件各自指定流程的需求出現再加。
  - 「誰來審」以規則外掛，新增業務不必改引擎。依賴方向是業務 → Flow → Organization／AccessControl，不成環。
  - 狀態只存在引擎：業務表只存申請內容（例如儲存庫與權限），不另存狀態。業務要判斷「是否有進行中的申請」時，把引擎的可組合查詢（`FlowService.PendingSubjects`）放進自己的 SQL。
  - 主管由 Organization 的主管鏈決定，與資料範圍同一個來源，不另建簽核用的主管設定。
- **取捨**：
  - 指派是快取：組織改了而排程還沒重算前，舊主管仍看得到待辦、新主管還看不到。決定時的即時重算保證不會由錯的人核准，但可見性不是即時的。
  - 主管依「目前」的主要所屬計算；申請途中調部門，會改由新主管審。
  - 只支援「任一人核准」；會簽、平行與退回補件等有需求時再加（新增欄位，不動既有資料）。
  - 參數以 JSON 存放，資料庫不檢查內容，改由規則的驗證器在儲存流程時檢查。
- **介面與通知**：
  - 頁面 `flow.approvals`（待我審核、我的申請、我審過的，給全員）與 `flow.definitions`（流程設定）；動作 `flow.approvals.manage`（代審、看全部申請、當備援審核人）。
  - 關卡啟動、結束時，通知中心（目標 `flow`）與郵件 outbox（類別 `flow.notice`）和簽核變更在同一交易寫入；等待超過 `Flow:RemindAfterDays` 的關卡由 `flow.reminders` 在工作日早上提醒。
