# 0004 模組可以互相依賴，但不可有循環

- **狀態**：採用（2026-10）
- **決定**：模組之間的目標是「沒有循環」，不是零依賴。`ModuleBoundaryTests.Module_dependencies_have_no_cycles` 直接禁止循環；跨模組讀取只透過對方的 `public` 服務，「A 發生後 B 跟著處理」的副作用用同交易的 domain event。

## 原因

- 零依賴會逼出大量只為轉送而存在的介面與 DTO 複本，讀者反而找不到真正的邏輯。
- 沒有循環就能由下往上讀懂、測試與修改；循環一旦出現，任何一端的改動都可能連鎖影響另一端。
- 曾經用「只能減少的基準線」逐步清除循環，清到 0 後改成直接禁止。

## 做法

造成循環時依序考慮：把型別移到真正擁有它的模組 → 下層定義介面、上層實作 → domain event → 下層方法改收自己的參數型別。詳見 [模組邊界](../architecture/MODULE_BOUNDARIES.md)。對話的讀取／匯出／複製／刪除留在 `Chat`，就是因為搬到 `Conversations` 會形成循環。
