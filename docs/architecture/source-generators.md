# Source generator

結論：編譯期就能決定的組合與樣板（模組清單、DI 註冊）由 source generator 產生，不在執行期反射掃描，也不維護集中清單。產生器都放在 `backend/src/AiNexus.Generators`，一個產生器一個資料夾。為什麼這樣做見 [ADR 0029](../decisions/0029-compile-time-composition.md)。

## 現有產生器

| 產生器 | 觸發 | 產出 |
| --- | --- | --- |
| [`FeatureCompositionGenerator`](../../backend/src/AiNexus.Generators/Composition/FeatureCompositionGenerator.cs) | `[FeatureComposition]`（`FeatureModules`） | 組件內每個模組的 `AddServices`、`MapEndpoints`（OpenAPI tag＝模組名）與 `VerifyStartup`；端點切片註冊為 scoped；FluentValidation 驗證器以 `IValidator<T>` 註冊為 singleton |

組合的規則：

- **模組**：實作 `IFeatureModule` 的非抽象、非泛型類別。`MapEndpoints`、`VerifyStartup` 有預設的空實作，只有模組自己實作時才產生呼叫。
- **切片**：類別有 static `Map*` 方法，且第一個參數是 `RouteGroupBuilder`。排除模組與 static、abstract、泛型類別。架構測試 `CompositionTests` 用反射重述同一條規則，對照產生的註冊。
- **驗證器**：實作 `IValidator<T>` 的非抽象、非泛型類別。
- **順序**：依完整型別名稱排序。順序固定但沒有意義，模組之間不可依賴註冊順序。消費 `IEnumerable<T>` 而在意順序的地方要自己排序，例如監控來源的 `Order`、總覽前端的 `ORDER`。
- **其他組件的模組**：產生器只看得到目前的組件，Data 專案的 `AppDatabaseModule` 由 `FeatureModules.AddFeatures` 明確註冊。

看產生的程式碼：在 IDE 方案總管的「相依性 → 分析器 → AiNexus.Generators」底下，或建置時加 `-p:EmitCompilerGeneratedFiles=true`，輸出在 `obj/<設定>/<目標框架>/generated`。

## 新增產生器

1. 在 `AiNexus.Generators/<名稱>/` 實作 `IIncrementalGenerator`。觸發點優先用 `ForAttributeWithMetadataName`，標記屬性放在 Platform。要找介面的實作時用 `CreateSyntaxProvider`，predicate 只做語法判斷。
2. pipeline 模型只放字串、數值與 `Common/` 的 `EquatableArray<T>`、`LocationInfo`、`DiagnosticInfo`。不放 `ISymbol`、`Compilation`、`SyntaxNode`、`Location`：它們讓快取比對失效，也讓舊的編譯結果無法回收。
3. 產出用 `SourceWriter` 寫（檔頭 `<auto-generated/>`、`#nullable enable`），型別一律寫 `global::` 開頭的完整名稱。
4. 使用端以 partial 方法宣告要產生的成員，和 `[LoggerMessage]` 一樣。少宣告一個會編譯失敗，不會悄悄少產生。產出只放直接呼叫，判斷邏輯留在手寫程式碼。
5. 診斷代碼為 `AINX` 加四位數，每個產生器占一個千位區段：`1xxx` 是 Composition。問題用 Error 級，指向原始碼位置。
6. 測試放在 `backend/tests/AiNexus.GeneratorTests` 的同名資料夾，用 `Support/GeneratorHarness` 編譯範例原始碼。至少驗證三件事：產出、診斷，以及無關的編輯讓各步驟沿用快取（每一步加 `WithTrackingName`）。產出若有執行期可以對照的事實，再加一個架構測試。
7. 使用產生器的專案以 `OutputItemType="Analyzer" ReferenceOutputAssembly="false"` 引用它，產生器不會進入發布輸出。

## 限制

- 產生器由編譯器載入，所以目標是 netstandard2.0、只依賴 Roslyn。Roslyn 套件的版本不可高於開發者會用到的最舊編譯器，目前是 5.0（`backend/Directory.Packages.props`）。
- IDE 每次按鍵都會重跑 pipeline：predicate 不做語意查詢，轉換裡不做 I/O，也不讀檔或環境變數（`EnforceExtendedAnalyzerRules` 會檢查）。
- 改了產生器以後，IDE 可能還載入著舊版；重開 IDE，或執行 `dotnet build-server shutdown`。
